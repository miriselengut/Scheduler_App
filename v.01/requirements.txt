# Weekly Client Scheduler

Administrator-only recurring weekly scheduler for:

- One provider
- 30-minute sessions
- One to five sessions per client each week
- Each client session on a different day
- Sunday through Thursday
- 2:00–6:00 PM and 8:00–11:00 PM
- Optimal and secondary client availability
- Appointment clustering
- Strong preference for at least two completely free evenings
- Proposed additions and edits that require administrator approval

## Main features

### Add a client

The **Add client** page includes:

- Name
- Location
- Notes
- Number of sessions needed each week
- A weekly calendar matching the schedule layout

Click a calendar box and choose:

- **Optimal**
- **Secondary**
- **Unavailable** remains the default

The number of weekly sessions cannot be greater than the number of different days on which the client is available.

### Edit a client

Every saved client has an **Edit client** button. You can change:

- Name
- Location
- Notes
- Sessions each week
- Optimal times
- Secondary times

The app recalculates the complete schedule after an edit. The saved client information and approved schedule remain unchanged until the edit proposal is approved.

The scheduler tries to:

1. Keep the client's current sessions when they still work.
2. Move only the edited client when necessary.
3. Rearrange another client only when no simpler valid solution exists.
4. Keep at least two evenings completely free whenever possible.

### Delete a client

The **Delete client** action permanently removes the client and all of that client's appointments. A confirmation is required.

## Response categories

1. **Works excellent** — all target-client sessions are optimal, no other clients move, and at least two free evenings remain.
2. **Works well** — at least one target-client session is secondary, no other clients move, and at least two free evenings remain.
3. **Works with rearranging** — one or more other clients must move.
4. **Works, but uses a protected evening** — feasible only with fewer than two completely free evenings.
5. **Cannot fit** — no valid schedule exists using the selected optimal/secondary times and current locks.

## Adding or editing a client workflow

1. Try the change while keeping every other client fixed and preserving two free evenings.
2. Try rearranging clients while preserving two free evenings.
3. Try the change while keeping every other client fixed without the two-free-evening requirement.
4. Try rearranging clients without the two-free-evening requirement.
5. If no solution exists, show **Cannot fit**.

The approved schedule is never overwritten immediately. A successful result is saved as a proposal and must be approved.

For an edit, the old name, location, notes, session count, availability, and schedule stay active until approval.

## Scheduling priorities

### Hard constraints

1. Every active client receives the selected number of 30-minute weekly sessions.
2. A client's sessions must occur on different days.
3. Only one client may occupy a time slot.
4. Appointments occur only in the configured Sunday–Thursday time slots.
5. A client may only be assigned to an optimal or secondary time.
6. Locked appointments cannot move.
7. Sessions per week cannot exceed the number of different available days.

### Optimization priorities

1. Avoid moving existing appointments.
2. Keep at least two evenings completely free.
3. Prefer optimal times over secondary times.
4. Keep appointments consecutive within each afternoon/evening block.
5. Use fewer separate appointment blocks when possible.

## How clustering works

Each day has two independent blocks:

- Afternoon: 2:00–6:00 PM
- Evening: 8:00–11:00 PM

The 6:00–8:00 break is not treated as a gap. The solver counts each new run of consecutive appointments as a segment and minimizes the number of segments.

Example:

- 2:00, 2:30, 3:00 = one segment
- 2:00, 3:00, 4:00 = three segments

## Database structure

The app automatically upgrades a database created by the original one-session version.

### `clients`

- `id`
- `name`
- `location`
- `notes`
- `sessions_per_week`
- `active` (retained for compatibility with the original database)
- `created_at`

### `client_availability`

- `client_id`
- `slot_key`
- `preference_level` (`optimal` or `secondary`)

### `assignments`

- `id`
- `client_id`
- `slot_key`
- `locked`
- `updated_at`

There can now be multiple assignment rows for one client.

### `proposals`

- `id`
- `target_client_id`
- `proposal_type` (`add` or `edit`)
- `status`
- `category`
- `message`
- `free_evenings`
- `moved_count`
- Proposed client name, location, notes, and sessions per week
- `created_at`
- `decided_at`

### `proposal_client_availability`

Stores the proposed optimal and secondary times for an add/edit proposal. This keeps edits from changing the saved client before approval.

### `proposal_assignments`

- `proposal_id`
- `client_id`
- `session_index`
- `old_slot_key`
- `new_slot_key`
- `preference_level`
- `change_type` (`added`, `moved`, `unchanged`, or `removed`)

## Install and run

Use Python 3.11 or newer.

```bash
python -m venv .venv
```

PowerShell temporary activation permission:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Move into the extracted project folder, then install packages:

```powershell
python -m pip install -r .\requirements.txt
```

Run the app:

```powershell
python -m streamlit run app.py
```

Run tests:

```powershell
python -m pytest
```

## Files

- `app.py` — Streamlit administrator interface
- `database.py` — SQLite tables, migrations, and database operations
- `solver.py` — OR-Tools scheduling model and response categories
- `constants.py` — weekdays and 30-minute slots
- `tests/test_solver.py` — core scheduling tests
- `requirements.txt` — required Python packages

## Current limits

- One provider
- Maximum five weekly sessions per client because the schedule has five days
- Location is stored but travel time is not optimized
- No login or external calendar synchronization yet

## Saved but unscheduled clients

A client who could not be placed may remain saved with no approved appointment.
That client does not participate in later scheduling checks unless you edit that
specific client. This prevents an older unscheduled client from blocking a new
client whose selected time is actually free.
